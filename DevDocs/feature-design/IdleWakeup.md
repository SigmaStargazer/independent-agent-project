# 功能设计原则 — Idle Wakeup 空闲唤醒

> **状态**：长期有效  
> **适用范围**：所有后续涉及 Agent 空闲唤醒、自主低频触发、空闲阶段环境提示的版本迭代  
> **最后更新**：2026-06-18

---

## 1. 功能定位

Idle Wakeup 的目标不是构建完整的注意力系统，也不是让 Agent 实时响应所有世界事件，而是在 Agent 长时间没有接到新输入时，以轻量、低频、带随机性的方式唤醒 Agent，让它有机会主动观察、回想、行动或继续等待。

本功能服务于一个核心体验目标：

> Agent 不应因为长期没有接到新信息而停在“永远不再主动行动”的状态。

---

## 2. 必须长期遵循的设计原则

### 2.1 空闲唤醒，而非事件推送总线

Idle Wakeup 只负责在 Agent 空闲后低频唤醒。它不应演变为“每个世界事件都实时广播给 Python，再由 Agent 逐条判断”的重型事件系统。

后续迭代中，若需要更强实时性，应另行设计事件感知 / 注意力系统，不应把 Idle Wakeup 扩展到过重。

### 2.2 Python 侧判断 Agent 是否空闲

Unity 只能较准确地知道 AIPlayer 身体是否处于 Idle，但不知道 Python LangGraph 是否正在运行、是否正在工具链中、是否刚完成一轮推理、是否还有队列消息。

因此 Idle Wakeup 的触发调度应以 Python Agent 运行时为准：

- 一轮 LangGraph 推理结束后开始计算空闲时间；
- timer 到期时再次确认 Agent 仍未运行；
- message / feedback 队列无待处理输入；
- 仍空闲时才注入空闲唤醒消息。

### 2.3 轻量化优先

Idle Wakeup 必须保持简单、可解释、低成本。默认不做：

- 复杂 salience / score 系统；
- per-Agent 感知缓冲；
- 每事件显著性评分；
- 每个 SceneObj 的注意力权重表；
- LLM 判断事件是否重要；
- 世界事件全量推送到 Python；
- 自动写入长期记忆。

如后续确需增加上述能力，应先明确它已经超出 Idle Wakeup 范围，并在新的功能设计文档中单独设计。

### 2.4 必须包含随机变量

Idle Wakeup 不应以完全固定的机械周期触发。至少应保留一个随机变量，例如：

- 随机空闲等待时间；
- 有事件与无事件时不同的随机区间；
- 小幅随机抖动。

推荐做法是“随机延迟”，而不是“随机决定是否唤醒”。这样既能避免行为过于机械，又便于调试和复现。

### 2.5 Agent 自主决定是否行动

Idle Wakeup 消息不应命令 Agent 必须行动，而应提供一个温和的空闲感知：

- 可以忽略；
- 可以继续等待；
- 可以观察周围；
- 可以回想近期世界事件；
- 可以主动采取行动。

文本应避免“请你立刻做出反应”之类强制措辞。

### 2.6 WorldEventLog 是按需素材，不是默认上下文

v0.20.10 的 WorldEventLog 可作为 Idle Wakeup 的近期事件素材来源，但不应每次都把完整事件日志注入 Agent。

推荐策略：

- 空闲唤醒时最多附带少量近期事件摘要；
- 摘要只包含对象、状态变化、相对时间等轻量信息；
- 若 Agent 需要完整上下文，由 Agent 自己调用 `get_world_event_log_cmd`。

### 2.7 低频与冷却优先

Idle Wakeup 必须有明确冷却，避免形成“空闲 → 唤醒 → 无动作 → 立刻再次唤醒”的循环。后续迭代应优先保证：

- 唤醒间隔有下限；
- 唤醒消息自身不会造成无限自激；
- 无新事件时唤醒频率更低；
- Agent 明确选择等待时，允许延长下一次唤醒间隔。

---

## 3. 推荐最小闭环

```text
Agent 完成一轮 LangGraph 推理
    ↓
Python 侧启动随机 idle timer
    ↓
期间若收到新消息 / 反馈 / 打断，则取消 timer
    ↓
timer 到期后再次确认 Agent 仍空闲
    ↓
可选：从 Unity 拉取少量 WorldEventLog 摘要
    ↓
向 Agent 注入 <空闲感知>
    ↓
Agent 自主决定忽略、观察、回想日志、移动、交流或继续等待
```

---

## 4. 文档维护要求

后续所有涉及 Idle Wakeup 的版本 PRD / 技术方案，必须引用本文档，并检查是否违反以下底线：

- 是否仍以“空闲唤醒”为目标，而不是变成实时事件总线；
- 是否仍由 Python 判断 LangGraph 空闲；
- 是否仍保持轻量化；
- 是否保留随机变量；
- 是否允许 Agent 忽略，不强迫行动；
- 是否避免把完整 WorldEventLog 默认注入上下文。
