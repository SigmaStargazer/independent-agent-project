# 需求：v0.23.0b 实现方式优化（Title 阶段零系统 / 进游戏初始化 / 回 Title 关闭 / UITitle 拆分）

> 本需求由 `DevDocs/Analysis/analysis_实现方式疑问.md` 的三点疑问转化而来。
> 原 v0.23.0a（Title API 配置 UI + Python 延迟初始化）已 commit；本版本在 a 版基础上优化实现方式。

---

## 架构原则（用户明确要求）

**追求对架构最干净的实现，而非改动最小；哪怕彻底重构也要避免架构腐化。**

核心生命周期模型：

```
Title 阶段：不应存在任何已初始化的系统（MemoryManager / AgentManager / EmbedderService 等一律未初始化）
进游戏时：  才 initialize（使用当前 api_config.json 的最新 Key）
回 Title 时：close（释放全部系统，回到「零系统」状态）
```

因此**不需要 reinitialize / 热更新**——Title 阶段本就没有已初始化系统，进游戏永远是一次全新初始化，自然使用最新配置。

---

## 需求 1：Title 阶段零系统，进游戏才初始化

### 背景

v0.23.0a 由「Title 点开始游戏 → UITitle 发 InitRequest」触发初始化，且 `--auto-init` 提供进程启动即初始化路径。用户期望更干净的生命周期：**Title 阶段任何系统都不应已初始化**。

### 目标

- Python 进程启动：仅监听端口，**不初始化任何系统**（无 Key 启动）。
- Title 场景：MemoryManager / AgentManager / EmbedderService 均为未初始化状态。
- 进游戏（StartGame / ContinueGame）：Flow 内触发初始化，使用当前 `api_config.json` 的最新 Key。
- `--auto-init`：仅作纯调试用途（进程启动即初始化，便于开发期快速联调），正式链路不依赖。

### 约束

- 进游戏初始化必须使用**当前** `api_config.json` 的最新值（每次进游戏都重新读取注入）。
- 与 `DeleteMemoryStep` / `RestoreMemoryStep` 内部自带的 close→initialize 行为兼容（见 v0.23.0a solution）。

---

## 需求 2：回 Title 时关闭全部系统

### 背景

若只做「进游戏初始化」而不做「回 Title 关闭」，则第一次进游戏后 MemoryManager 等会持续存在；第二次改 Key 后再进游戏，`_llm_with_tools` / `MemoryManager._initialized` 等缓存会导致仍用旧 Key——这正是「必须重启进程」的根因。

### 目标

- 回 Title（ReturnToTitleFlow）时，**关闭全部已初始化系统**，回到「Title 阶段零系统」状态：
  - `AgentManager`：移除全部 Agent（aremove_all）
  - `MemoryManager`：close（复位 `_initialized`，释放 worker/graphiti/driver）
  - `DBConnectionService`：close（释放 Kuzu 连接）
  - `EmbedderService`：close（释放 embedder/reranker，**当前缺失，需补**）
  - Agent LLM 缓存：清空（`get_llm_with_tools` 的 `_llm_with_tools`，**当前缺失，需补**）
- 之后再次进游戏 = 全新初始化 = 使用最新 Key。

### 约束

- **切关（NextMapFlow）不得触发关闭**：它只在游戏内进行（Interrupt → Backup → LoadScene → Start），记忆系统保持运行。
- 关闭必须幂等、可重复（Title 阶段可能多次进出）。

---

## 需求 3：UITitle 拆分，配置读写下沉到 UISetting

### 背景

v0.23.0a 中 `UITitle.cs` 同时承担「页面切换」与「API 配置读写」（12 个 InputField、Load/Save、变更检测、入口校验），职责混杂。

### 目标

- 新增 `UISetting`（挂载在 UIConfig 上）：承担 API 配置的读取、回填、变更检测、保存/取消、完整性校验。
- `UITitle` 仅保留页面切换（PressAnyButton/MainMenu/Config/4 子面板）、ESC 分发、弹窗开关。
- 入口（OnClickNewGame/OnClickContinueGame）调用 `UISetting` 的校验结果，成功后进 GameFlow。
- `UITitle` 不再发 InitRequest（初始化由 Flow 内 Step 触发）。

---

## 验收标准（草案）

1. Python 启动（不带 `--auto-init`）后，Title 阶段 MemoryManager / AgentManager / EmbedderService 均未初始化；改 `api_config.json` 后不重启进程也能在下次进游戏生效（因为每次都全新初始化）。
2. 进 NewGame / ContinueGame Flow → `InitializeStep` 触发初始化，使用最新 Key。
3. 回 Title → `CloseStep` 关闭全部系统（Python 日志确认 close）；再进游戏重新初始化且用最新 Key。
4. 切关 NextMapFlow 不触发关闭，记忆系统保持运行。
5. `UITitle` 不再包含任何 API 配置读写逻辑；`UISetting` 独立可绑定 12 个 InputField。
6. 场景中 UITitle 的 12 个 InputField 引用迁移到 UISetting（更新绑定指引）。
