## 2. 保存配置弹窗按钮绑定（三按钮：取消 / 退出 / 保存并退出）

`MsgboxSaveSetting` 是**三按钮**弹窗，语义如下（ESC 在弹窗内触发 Btn1）：

| 按钮 | 文案 | 行为 | 绑定到 |
|------|------|------|--------|
| **Btn1** | 取消 | 只关弹窗，**停留在当前子面板**（不切换） | `UITitle.CloseSaveConfigMsgBox` |
| **Btn2** | 退出 | **不保存**，关弹窗 → **回上一层**（子面板→设置 / 设置→主菜单） | `UISetting.OnCancelSaveConfig` |
| **Btn3** | 保存并退出 | **保存**，关弹窗 → **回上一层**（子面板→设置 / 设置→主菜单） | `UISetting.OnConfirmSaveConfig` |

> **职责划分**：
> - `UISetting.OnConfirmSaveConfig` / `OnCancelSaveConfig`：保存/不保存 + 关弹窗 + 发「回上一层」请求（**不持有面板引用**，通过 `OnRequestBack` 回调请求 UITitle）。
> - `UITitle.CloseSaveConfigMsgBox`：只关弹窗停留当前层；`OnRequestBackFromSaveMsg` 收到回调后执行真正的面板切换（`ShowSetting` / `ShowMainMenu`）。
>
> **绑定操作**（目标对象）：
> - Btn3「保存并退出」：目标 = **UIConfig 上的 UISetting**，方法 `OnConfirmSaveConfig`
> - Btn2「退出」：目标 = **UIConfig 上的 UISetting**，方法 `OnCancelSaveConfig`
> - Btn1「取消」：目标 = **UITitle**，方法 `CloseSaveConfigMsgBox`
>
> **关键**：`UITitle.Awake` 会自动给 `UISetting.OnRequestBack` 注入回调（前提 `UITitle.mSetting` 已绑定到 UIConfig 上的 UISetting）。若未绑定，保存/退出后弹窗会关但不会回退层面板。

## 4. 入口按钮（逻辑变化，无需重新绑定）

`新游戏` / `继续游戏` 按钮 `OnClick` 仍指向 `UITitle.OnClickNewGame` / `UITitle.OnClickContinueGame`（方法名未变），**无需重新绑定**。

但 b 版逻辑已变化（代码内接管）：
- a 版：校验完整 → 在 Title 发 `InitRequest` → 等待初始化 → 进 Flow。

> 玩家体验差异：点「新游戏/继续游戏」后不再有「Title 内等待初始化」的中间态，加载界面直接显示 Flow 进度（`InitializeStep` 是第一步）。

## 9. v0.23.0b 后续修复记录（2026-08-21）

> 针对联调发现的 3 个问题，均为 **Python 侧 + Unity 脚本侧**改动，**无需新的场景绑定**（下述说明项已由代码自动处理）。

### 9.1 问题 1：配置完成后重进，模型名称（Model）不显示

**根因**：TMP_InputField 默认 `restoreOriginalTextOnEscape = true`——按 **ESC** 时 Unity 会把输入框**恢复为进入编辑前的原始文本**（撤销用户输入），与 `UITitle` 用 ESC 做「退出子面板 + 变更检测」的机制冲突：
- 用户改 Model → 按 ESC → 输入框先被 TMP 还原为旧值（空）→ `HasConfigChanged` 检测不到变化 → 不弹保存确认 → 修改丢失 → 重进 Model 仍空。

**修复**：`UISetting.Awake()` 统一把 12 个输入框的 `restoreOriginalTextOnEscape` 设为 `false`（代码自动，**无需在 Inspector 逐个改**）。ESC 不再撤销用户输入，变更检测与保存恢复正常。

### 9.2 问题 2：只改一个值 ESC 不弹保存确认；改多个值只保存第一个

**根因**：与 9.1 同源（`restoreOriginalTextOnEscape` 的 ESC 还原行为）。多个输入框时，ESC 只还原**最后聚焦**的输入框，导致「只保存第一个修改的值」。

**修复**：同 9.1，`Awake` 关闭还原行为后，ESC 保留全部输入框编辑值，`HasConfigChanged` 与 `CollectInputsToApiConfig` 正常收集全部 12 项。

### 9.3 跨语言键名不一致（Python 读不到配置）

**根因**：`ApiConfigStore` 原用 `JsonUtility` 序列化 `ApiConfig`，字段名为**小写驼峰**（如 `agentModel`）；但 Python `config/api_config_loader.API_CONFIG_KEYS` 读的是**大写键**（如 `AGENT_MODEL`），实测注入 0 项——Python 完全读不到 Unity 保存的配置。

**修复（方案 A）**：`ApiConfig` 全部 12 个字段名改为与 Python `API_CONFIG_KEYS` **完全一致的大写键名**（`AGENT_API_BASE` / `AGENT_API_KEY` / `AGENT_MODEL` / `MEMORY_*` / `EMBEDDING_*` / `RERANKER_*`）。`JsonUtility` 序列化出的 `api_config.json` 即 Python 可直接读取的格式。已移除不再需要的 `ToDictionary` / `FromDictionary`。
- **数据迁移**：旧的小写 `api_config.json` 已迁移为大写键（备份为 `api_config.json.bak`）。若编辑器下仍有旧格式文件，重新在 Title 保存一次配置即可覆盖。
- **验证**：`load_api_config_into_env(force=True)` 现可注入 11 项（`RERANKER_MODEL` 为空不注入），`AGENT_MODEL` 正确读取。
