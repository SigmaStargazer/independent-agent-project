## 1. 背景与目标

现有 `Assets/Rendering/Shaders/Wall/SG_Wall 2.shadergraph` 用于墙面、地面贴图平铺，已满足：

1. 每格大小由 `Vector2 TileSize` 决定，缩放物体不改变格大小（基于世界空间 Position 平铺）。
2. 使用 `Texture2D HeightMap` + Parallax Occlusion Mapping 实现墙面凹凸。

但**无法满足第 3 点**：贴图朝向不随物体旋转调整。旋转墙面/地面物体时，贴图网格仍锁定在世界 XY 轴，导致贴图方向与物体朝向不匹配（例如墙旋转 90° 后，砖纹方向不变）。

**目标**：在不破坏前两点的前提下，让贴图平铺的两个轴跟随物体的本地旋转，使贴图方向与物体朝向一致。

## 2. 范围

### 2.1 本期包含

- 分析 `SG_Wall 2.shadergraph` 当前 UV 生成方式的根因。
- 提出使贴图朝向跟随物体旋转的技术方案。
- 修改 Shader（或新建 Shader）实现第 3 点需求。
- 保留 `TileSize` 世界尺度平铺 + HeightMap 凹凸两项已有行为。

### 2.2 本期不包含

- 不改 HeightMap / Parallax Occlusion Mapping 的凹凸算法本身。
- 不引入新的贴图资源。
- 不涉及 Python / 协议 / Agent 任何改动（纯 Unity 渲染层）。

## 4. 功能需求

### 4.1 贴图朝向跟随物体旋转

- Shader 生成的平铺 UV 两个轴，应基于**物体本地空间**的两个正交方向，而非世界 XY 轴。
- 旋转物体后，贴图应整体跟随旋转，视觉上「贴在物体表面」。
- 平铺格大小仍以 `TileSize`（世界单位）控制，缩放物体不改格大小。

### 4.2 兼容现有行为

- 保留 `TileSize`（Vector2）、`HeightMap`（Texture2D）等现有属性。
- 保留 Parallax Occlusion Mapping 凹凸效果。
- 物体旋转为 0 时，渲染结果与现版本一致（无回归）。

## 5. 非功能需求

- **性能**：不显著增加 GPU 开销；优先使用 Shader Graph 内置节点，避免 Custom Function / HLSL 除非必要。
- **兼容性**：目标 Unity 2021.3.8f1c1，URP Shader Graph。
- **可维护性**：方案应在 Shader Graph 中可视化、可调试。

## 6. 验收标准
