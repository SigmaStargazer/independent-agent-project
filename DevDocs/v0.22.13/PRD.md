# PRD - v0.22.13 相机移动范围限制

> **状态**：已确认
> **对应需求**：`requirements/相机移动范围限制.md`
> **最后更新**：2026-07-27

---

## 1. 背景与目标

现有 `CameraController.cs` 通过 `SmoothDamp` 平滑跟随 `HumanPlayer`，但没有任何范围约束：当玩家移动到场景边缘时，相机会看到边界墙之后的内容（天空盒/空白区域），造成"穿帮"。

本次目标：给相机增加一个**矩形移动范围**约束，使相机在任何时刻，其视口的四条边都不超出该矩形；并且该矩形能在 Scene 视图中**通过拖拽直观配置**大小与位置。

## 2. 范围

### 2.1 本期包含

- 在 `CameraController` 中实现"视口四边不超出矩形"的 clamp 逻辑（正交相机）。
- 提供一个可在 Scene 视图中拖拽调整的矩形边界配置方式（可视化 Gizmo + 序列化字段）。
- 相机在 `SmoothDamp` 平滑跟随后，再对位置做 clamp，确保最终位置始终合规。
- 支持运行时切换宽高比/分辨率时仍正确限制（动态计算视口半宽/半高）。

### 2.2 本期不包含

- 不改造跟随逻辑本身（x/y 偏移量 `(isRight ? 3 : -3, 2)`、`smoothTime` 保持不变；z 的处理见 §4.2，不再硬编码 `-10`）。
- 不引入 Cinemachine 等第三方相机方案。
- 不做相机缩放/变焦限制，不做相机旋转。
- 不做动态边界（边界随关卡事件变化）。本期边界为静态矩形，每个场景可单独配置。
- 不修改 Python 侧、不涉及协议、不涉及 Agent 工具链路。

## 3. 用户与场景

## 4. 功能需求

### 4.1 矩形边界配置

- 提供一个矩形边界配置，支持在 Scene 视图中**可视化拖拽**调整矩形的位置与大小。
- 矩形以世界坐标定义（xmin/xmax/ymin/ymax 或 center+size 两种等价表示之一）。
- 配置项需序列化，场景保存后生效。
- 在 Scene 视图中绘制矩形线框 Gizmo，便于在编辑态直观看到范围。

### 4.2 相机位置 clamp

- 相机位置经过 `SmoothDamp` 平滑后，必须再经过 clamp，保证最终 `transform.position` 使**视口四边**位于矩形内或恰好在边界上。
- "视口最左侧 = 矩形最左侧"的语义：相机视口的左/右/上/下边在世界坐标下分别不超过矩形的左/右/上/下边。
- 正交相机视口半宽 = `orthographicSize * Screen.width / Screen.height`，半高 = `orthographicSize`；clamp 时据此计算相机中心允许的移动区间。
- z 轴（相机深度）不受 clamp 影响；运行时锁定为启动时的深度（`Start` 时缓存 `transform.position.z`），不再硬编码 `-10`，便于在 Scene 中调整相机深度后保持。

### 4.3 边界缺失/未配置时的行为

- 当矩形未配置（如默认零尺寸或未勾选启用）时，相机行为退化为当前不限制的跟随逻辑，不报错、不卡死。

## 5. 非功能需求

- **性能**：clamp 仅在 `LateUpdate` 末尾做一次轻量运算，无额外开销。
- **兼容性**：仅依赖 Unity 标准 API（`Camera`、`Gizmos`、`Screen`），不引入新依赖。
- **可观测性**：Scene 视图 Gizmo 在选中相机对象时清晰可见，颜色与手柄便于辨识。
- **编码**：C# 文件 UTF-8 无 BOM（遵循项目编码基线）。

## 6. 验收标准

- [ ] 玩家移动到场景任意边缘，相机视口四条边均不超出配置矩形。
- [ ] 在 Scene 视图中可通过拖拽直观调整矩形的大小与位置。
- [ ] Scene 视图中绘制矩形线框 Gizmo，选中相机即可看到当前范围。
- [ ] 改变 Game 窗口宽高比（如 Free Aspect 切换 16:9 / 4:3）后，相机仍被正确限制在矩形内。
- [ ] 矩形未启用或未配置时，相机行为与改造前一致（平滑跟随、不穿帮逻辑不强制生效）。
- [ ] 在 Scene 中调整相机 z 深度后运行，相机深度保持为该初始值，不被硬编码 `-10` 覆盖。
- [ ] 改造未破坏现有跟随手感（平滑度、偏移量不变）。
