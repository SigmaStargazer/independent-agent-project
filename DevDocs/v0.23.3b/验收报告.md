## 1. 验收范围与方法

本期目标：把 Python 端 `main.py` 打成自包含 `agent_server.exe`（PyInstaller onedir + `--noconsole`），由 Unity 打包版托管（启动拉起、退出清理、无窗口），开发态不受影响。

验收分两层：

| 层 | 范围 | 方法 |
|----|------|------|
| **开发态** | 编辑器 + `uv run python main.py`，路径/行为与改造前一致 | 手动回归：启动、连接、新游戏、续玩 |
| **打包态** | `Build/PythonServer/agent_server.exe` + Unity 打包版 | 手动全流程：启动→进 Title→进游戏→Agent 推理→退出清理 |

## 2. 最终版本与方案设计的差异

> 以下差异均已在代码中核对。总体结论：**实际实现比方案设计更收敛、更稳**，无功能缺失。

| # | 方案设计（solution.md） | 最终实现 | 差异说明 |
|---|------------------------|----------|----------|
| 1 | `path_config.py` 单文件，`get_port_config_file()` 挂 `get_runtime_root()/Data/Config` | 落地为 `runtime/` 包，`path_config.py` + `single_instance.py` + `__init__.py` | **新增** `runtime/` 包；`single_instance.py` 是联调中新增的单实例互斥（设计里多开防线只靠「绑定端口失败」+ Unity TCP 探测，实际发现随机端口下无法靠端口失败，改用 PID 文件） |
| 2 | 只有 `get_runtime_root()` 一个「根」概念，`Data/Config` 也在其下 | 拆出 `get_config_root()`（`runtime_root` 的上级），`get_port_config_file()`/`get_api_config_file()` 挂 `config_root/Data/Config` | **比设计更正确**：开发态下 `runtime_root=PythonServer`、`config_root=Src`，与现状 `Src/Data/Config` 完全一致，避免开发态路径回归（这是设计阶段已预判并修正的语义） |
| 3 | 方案未提多开互斥的 Python 侧实现 | `runtime/single_instance.py`（PID 文件 + psutil 存活检测），`main()` 开头 `acquire_single_instance()` | **联调新增**（见 §3 修复点 6） |
| 4 | 方案只列 `build_python_exe.cmd` 打包 + 复制 `Data/Lib/config/db` | 实际脚本**不复制 `Lib/`**（`Src/Lib/proto` 只有 `.proto` 源，运行时实际用 `network/message_pb2.py`，已由 PyInstaller 自动收集）；**不复制 `.env`**（打包版启动即无 Key 模式，见 PRD §4.4） | 打包产物比设计更精简；注释里已说明理由 |
| 5 | 打包输出 `distpath=Build/PythonServer` | 实际 PyInstaller `onedir` 输出到 `Build/agent_server/`，脚本 `move` 到 `Build/PythonServer/` | 实现细节（PyInstaller `--distpath` 行为），结果一致 |
| 6 | 多开互斥：Unity 启动前 TCP 探测（读端口文件 + 连接） | 实现一致（`IsPythonAlive()` 读 `JsonConfigIO.ConfigDir()` 端口文件 + TCP 探测），另有 Python 侧 PID 文件双保险 | 与设计一致 + Python 侧增强 |
| 7 | `Shutdown()`：发 CloseRequest → `_process.WaitForExit(2000)` → Kill | 实际用 `AgentClient.Instance.Connected` 判断是否发 CloseRequest；进程定位 `_process ?? ResolveRunningProcess()`（读 PID 文件） | **覆盖「复用已有实例」场景**（联调修复点，见 §3 修复点 5） |
| 8 | 退出清理触发：`BootstrapEntry.OnApplicationQuit` | 实际为 `[RuntimeInitializeOnLoadMethod]` 静态注册 `Application.quitting`，`BootstrapEntry.OnApplicationQuit` 仅作双保险 | **比设计更可靠**（联调修复点 5） |
| 9 | 方案提到 `AGENT_SERVER_ROOT` 环境变量优先级 | 实现保留（`path_config.get_runtime_root()` 第 1 优先级） | 与设计一致 |
| 10 | `db/` 可写自检（方案 B） | 实现 `ensure_runtime_writable()`，仅在 `sys.frozen` 时检查，开发态跳过 | 与设计一致 |
| 11 | Kuzu 打开路径直接使用 | 实际增加 **NTFS junction** 中文路径规避（`_kuzu_safe_path`） | **联调新增**（修复点 4），设计风险表 E9 已预判中文路径问题，实际必须处理 |

## 3. 这些天修正的点（复盘）

> 共 **6 类** 修复，全部记录于 `solution.md` §7 实现记录，此处展开根因与影响。

| # | 日期 | 问题 | 根因 | 修复 | 影响 |
|---|------|------|------|------|------|
| 1 | 08-28 | 打包 exe 首次 `print()` 崩溃 `AttributeError: 'NoneType' object has no attribute 'write'` | `--noconsole` 打包为 GUI 子系统进程，`sys.stdout/stderr` 为 `None`，`console_logger.TeeWriter` 拿到 `None` 直接 `.write()` | `_NullStream` 兜底，`TeeWriter._original` 为 `None` 时替换 | 打包版启动不再崩溃；日志仍落盘 |
| 2 | 08-28 | Agent 无法接收消息，`Unknown encoding cl100k_base` | PyInstaller 未收集 `tiktoken_ext` 命名空间包（内含 `openai_public.py` 编码定义） | `build_python_exe.cmd` 加 `--collect-all tiktoken_ext` / `--hidden-import tiktoken_ext.openai_public` | 记忆/token 计算正常 |
| 3 | 08-28 | 退出 Unity 后 Python 进程残留（验收不通过） | ① `BootstrapEntry` 挂在 Bootstrap 场景对象，`LoadScene("Title")` 后对象销毁，`OnApplicationQuit` 不再触发；② 复用已有实例时 `_process` 为 `null`，`Shutdown()` 直接 return | `[RuntimeInitializeOnLoadMethod]` 静态注册 `Application.quitting` + `Shutdown()` 读 PID 文件定位进程 | 正常/异常/强制退出均清理 |
| 4 | 08-29 | 删库后 `Cannot open file` / `UnicodeDecodeError` | Kuzu C++ 底层用 `CreateFileA`（ANSI），含中文绝对路径新建库失败 | NTFS junction（`mklink /J`）把含非 ASCII 的 db 目录映射到 `%TEMP%\pskuzu\<hash>` 纯 ASCII 路径，按 db 路径 hash 隔离 | 中文路径下新建/打开/删除/重建均正常；不同运行根不互相抢锁 |
| 5 | 08-29 | `requests` 缺 CA 证书 `FileNotFoundError: cacert.pem` | PyInstaller 未收集 `certifi` 数据文件 | `build_python_exe.cmd` 加 `--collect-all certifi` | HTTPS 请求正常 |
| 6 | 08-29 | 编辑器读到的 API Key 为空 | `api_config.json` 字段名 camelCase（`agentApiKey`）与 Unity `JsonUtility` / Python `API_CONFIG_KEYS` 的 SCREAMING_SNAKE_CASE 不一致（大小写敏感） | `api_config.json` 字段统一为 `AGENT_API_KEY` 等 12 项 | 编辑器/打包版读 key 正常 |

**流程复盘（教训）**：

1. **PyInstaller 收集问题的系统性**：`tiktoken_ext`、`certifi` 两个都是「数据/命名空间包未被收集」的同源问题，但症状完全不同（一个 `Unknown encoding`、一个 `FileNotFoundError`），排查各自消耗了轮次。**教训**：打包新依赖后，应主动检查其数据文件是否被 PyInstaller 收集（`--collect-all`），而不是等运行时崩溃。
2. **中文路径是打包态才暴露的雷**：Kuzu 中文路径问题在开发态（`Src/PythonServer` 路径含中文）其实一直存在，但之前一直用相对路径 `db`（工作目录恰好在 PythonServer 下）掩盖了它；改成绝对路径（v0.23.3b path_config）后才暴露。**教训**：绝对路径改造必须同步排查底层库对非 ASCII 路径的兼容性。
3. **进程清理要覆盖「复用」分支**：设计时只想到「自己拉起的进程」，漏了「复用已有实例」时 `_process` 为空的场景。**教训**：凡是「进程生命周期管理」，必须枚举所有获得进程引用的路径。
