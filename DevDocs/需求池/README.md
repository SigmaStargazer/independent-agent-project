# 需求池（候选问题与候选需求）

本目录是**不依附于具体版本**的长期候选池，与 `DevDocs/vX.Y/` 版本目录是平级关系。

## 用途

- 验收某版本时发现「与本版无关、但需后续处理」的问题，先记到这里。
- 平时灵感、待验证想法、跨多版本才会推进的方向，也先记到这里。
- **不要把这里的条目当作已立项需求**；只是冷备清单。新版本启动时，再从中挑题正式立项，并把对应条目迁移到新版本目录的 `analysis.md` / `requirements/`。

## 文件约定

| 文件 | 用途 |
|------|------|
| `backlog.md` | 候选问题与候选需求清单。开头是索引表（类型 / 影响 / 优先级 / 状态 / 立项版本），下方按 P0/P1/P2 顺序展开正文 |
| 其他附件 | 复现日志截选、设计草图等，按主题命名 |

> 旧名 `analysis.md`，2026-06-28 改名为 `backlog.md`，与各版本目录内的 `analysis.md`（版本分析文档）做语义区分。

## 协作约定

- 新增条目时请补：现象、根因（如已知）、候选方向、影响范围预估、复现日志路径，并在开头索引表追加一行。
- 优先级建议：P0（影响验收 / 阻断后续训练）、P1（明显体验问题）、P2（长期改进 / 评估类）。
- 立项时把条目从 `backlog.md` **整段剪切**到新版本目录的 `analysis.md` 或 `requirements/` 下；同时把索引表对应行的「状态 / 立项版本」更新为「已立项 / vX.Y」，避免重复来源。

- 2026-06-28：`analysis.md` 改名为 `backlog.md`，并新增开头索引表。
