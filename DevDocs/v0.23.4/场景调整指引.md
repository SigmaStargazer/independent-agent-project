## 1. 新增 `MsgboxEmptyApiKey`（需求一，配置不完整提示）

基于现有 `Msgbox.prefab`（`UIMsgBox` 组件）新建一个弹窗，用于「当前模型配置 Panel 有文本框为空时按 ESC」的提示。

### 1.1 创建弹窗对象

在 Title 场景 **UI 根节点** 下新建（或复制现有 `MsgboxSaveApiKey` 修改）：

- 命名：`MsgboxEmptyApiKey`，挂 **`UIMsgBox`** 组件（必须有，否则 `AnyActive` / ESC 逻辑不工作）。
- 挂完先保持 `SetActive(false)`（`UITitle` 的 `Awake` 也会自动隐藏新增弹窗引用）。

### 1.2 文案（场景静态文案，无需走代码）

| 元素 | 文案 |
|------|------|
| 标题 | 配置不完整（或按需） |
| 提示正文 | 有模型配置项为空，无法测试保存 |
| Btn1 | 继续配置 |
| Btn2 | 退出 |

> `Btn3` 无需配置——`UIMsgBox` 会自动隐藏未配置的按钮。

### 1.3 按钮 OnClick 绑定

| 按钮 | 行为 | 绑定到 |
|------|------|--------|
| **Btn1** 继续配置 | 关弹窗，留在当前 Panel | `UITitle.OnClickEmptyContinue` |
| **Btn2** 退出 | 关弹窗，返回 `PanelTab`（不保存） | `UITitle.OnClickEmptyExit` |

### 1.4 UITitle 引用拖拽

选中挂 `UITitle` 的对象，Inspector 序列化字段拖入：

| UITitle 字段 | 拖入对象 |
|--------------|----------|
| `Empty Api Key Msgbox`（`mEmptyApiKeyMsgbox`） | `MsgboxEmptyApiKey` GameObject |

## 2. 设置页 `PanelSetting`（根容器）+ `PanelTab` 多 Tab 化（需求二，数据驱动架构）

### 2.1 场景结构调整

**现状**：场景中 `ContentModelConfig`（含 4 个配置按钮）是 `PanelSetting` 的直接子节点；`UISetting` 挂在 `PanelSetting` 上；4 个配置子面板（`PanelLLMAgent`/`PanelLLMMemory`/`PanelEmbedding`/`PanelRerank`）是 `Canvas/UI` 下与 `PanelSetting` 平级的节点。

**本次要做（用户最终层级）**：

```
PanelSetting（根容器；唯一脚本：UISetting = Tab 导航 + 协调 + 画面配置；放设置期间背景图；配置期间保持激活）
├── PanelTab（Tab 按钮 + 内容区容器）
│   ├── TabModelConfig（「模型配置」按钮）
│   ├── TabDisplaySettings（「画面」按钮）
│   ├── ContentModelConfig（已存在；挂 UIModelConfig；内含 4 个配置按钮，绑定不变；默认显示）
│   ├── ContentDisplaySettings（新增：画面 Tab 内容区，不挂脚本；显示模式行 + 分辨率行）
│   └── ContentGameSettings（本期不创建；预留「游戏」Tab）
├── PanelLLMAgent（已存在，移入 PanelSetting；挂 UILLMAgent）
├── PanelLLMMemory（已存在，移入 PanelSetting；挂 UILLMMemory）
├── PanelEmbedding（已存在，移入 PanelSetting）
└── PanelRerank（已存在，移入 PanelSetting；挂 UILLMRerank）
```

具体操作：

- **把 4 个配置子面板**（`PanelLLMAgent`/`PanelLLMMemory`/`PanelEmbedding`/`PanelRerank`）**从 `Canvas/UI` 移入 `PanelSetting`**（与 `PanelTab` 平级互斥）。
- **新增 `PanelTab`**（`PanelSetting` 的子节点）：Tab 按钮容器 + 内容区容器。
- **`ContentDisplaySettings`**（新增，`PanelTab` 的子节点）：画面 Tab 内容区，搭建 显示模式行 + 分辨率行（Text + 左右箭头按钮）。
- **`ContentModelConfig`**：已存在，**挂 `UIModelConfig`**（模型配置数据组件），保持原有点击绑定不变，默认显示。
- **`ContentGameSettings`**：本期**不创建**（预留「游戏」Tab，放语言设置等）。
- **背景图**：放 `PanelSetting` 上（PanelTab 与 4 个配置子面板共用，切换不闪）。

### 2.2 画面页内容区（`ContentDisplaySettings`）搭建

画面配置逻辑**并入 `UISetting`**（挂 `PanelSetting`，配置期间常驻），通过引用驱动 `ContentDisplaySettings` 内控件。Inspector 拖拽（字段名以实际编译为准）：

| `UISetting` 字段 | 拖入对象 |
|------------------|----------|
| `Display Mode Text`（`mDisplayModeText`） | 显示模式当前值文本（如「窗口化」） |
| `Display Mode Left`（`mDisplayModeLeft`） | 显示模式左箭头按钮（◀） |
| `Display Mode Right`（`mDisplayModeRight`） | 显示模式右箭头按钮（▶） |
| `Resolution Text`（`mResolutionText`） | 分辨率当前值文本（如 `1920 x 1080`） |
| `Resolution Left`（`mResolutionLeft`） | 分辨率左箭头按钮（◀） |
| `Resolution Right`（`mResolutionRight`） | 分辨率右箭头按钮（▶） |

> 左右箭头按钮的 OnClick **不手动绑定**——`UISetting` 内部自己绑定加减逻辑与边界禁用。只需把按钮拖到对应字段。

### 2.3 Tab 按钮与内容区绑定（数据驱动）

选中 `PanelSetting` 上的 **`UISetting`** 组件，找到其数组字段 **`Settings Tabs`（`mSettingsTabs`，`SettingsTabConfig[]`）**，按 Tab 顺序填入两项：

| 数组项 | `Tab Button` | `Content` | `Title Key` |
|--------|--------------|-----------|-------------|
| 0 | `TabModelConfig` | `ContentModelConfig` | `tab_model_config` |
| 1 | `TabDisplaySettings` | `ContentDisplaySettings` | `tab_display_settings` |

> **关键**：`mSettingsTabs` 数组长度 = Tab 数量，`UISetting` 遍历它自动生成切换逻辑（Tab 按钮 **不要**手动绑 OnClick）。未来加 Tab（如「游戏」）只需数组加一项 + 场景加内容区，**无需改代码**。`UITitle` 不参与面板内 Tab 切换。
>
> **`Title Key` 是枚举下拉框（非手填字符串）**：类型为 `UITextKey`，策划在 Inspector 下拉选择即可，避免拼错。枚举成员名即 `strings_zh_CN.json` 中的 key；选 `None` 表示不赋值（Tab 标题用场景手动配置的中文，二选一）。

### 2.4 Tab 标题文案（数据驱动，枚举选择）

Tab 按钮标题走数据驱动：`UISetting.RefreshTabTitles` 按 `titleKey`（`UITextKey` 枚举）经 `UITextProvider` 赋给 Tab 按钮下子 Text。**无 `mTabTitleRoot` 拖拽**——只需在 `mSettingsTabs` 数组每项的 `Title Key` 下拉里选 `tab_model_config` / `tab_display_settings` 即可（选 `None` 则用场景里手动填的中文）。

## 2.5 启用 `MsgboxSaveSetting`（需求三，画面变更保存确认）

复用现有 `MsgboxSaveSetting`（`UITitle.mSaveSettingMsgBox`，场景中已存在，`Msgbox.prefab` 三按钮弹窗），三按钮 onClick 绑定：

| 按钮 | 行为 | 绑定到 |
|------|------|--------|
| **Btn1** 保存并退出 | 保存画面设置（写 `game_settings.json`），返回 `PanelMenu` | `UITitle.OnClickSaveSettingAndExit` |
| **Btn2** 退出 | **还原画面设置为已保存值（实际分辨率/模式与面板数值一并还原）**，返回 `PanelMenu` | `UITitle.OnClickExitSetting` |
| **Btn3** 取消 | 仅关闭弹窗，留在设置页 | `UITitle.OnClickCancelSaveSetting` |

> 触发：`PanelTab` 按 ESC 退出设置页时，若 `UISetting.HasDisplaySettingsChanged()` 为 true 则弹此窗；无变更直接返回主菜单。
> **Btn2「退出」的还原**：`UISetting.RevertDisplaySettings()` → `RevertGameSettingsCommand` 把 Model 还原为文件已保存值，经 `BindableProperty` 订阅自动 `ApplyScreen + 刷新 UI`，因此点箭头已生效的实际分辨率/模式也会还原。

## 3. 画面设置持久化

- 代码侧已实现 `GameSettingsStore`，复用 `JsonConfigIO`，读写 `Data/Config/game_settings.json`（UTF-8）。
- **无需场景绑定**；首次运行（文件不存在/为空/解析失败）时使用默认值：**显示模式 = 全屏（`ExclusiveFullScreen`）+ 分辨率 = 1920x1080**（由 `GameSettingsStore` 的 `kDefaultMode=2 / kDefaultRes=2` 定义，对应 `UISetting` 的 `kModes[2]` / `kResolutions[2]`）。
- 用户保存过设置后，`game_settings.json` 生成，此后以文件值为准。
- `game_settings.json` 建议加进 `.gitignore`（可选，由 Agent 处理）。

## 5. 验收自检（v0.23.4）

### 需求一（MsgboxEmptyApiKey）
1. 模型配置 Panel 中某文本框**清空** → 按 ESC → 弹 `MsgboxEmptyApiKey`（而非 `MsgboxSaveApiKey`）。
2. `MsgboxEmptyApiKey` 点「继续配置」→ 关弹窗，留当前 Panel。
3. `MsgboxEmptyApiKey` 点「退出」→ 关弹窗，返回 `PanelTab`（不保存）。
4. 文本框**全非空且有变更** → 按 ESC → 仍弹 `MsgboxSaveApiKey`（不回归）。
5. 文本框**无变更** → 按 ESC → 直接返回 `PanelSetting`（不弹窗，不回归）。

### 需求二（多 Tab + 画面）
6. 打开 `PanelSetting` → 显示多 Tab，默认第一个「模型配置」，4 个配置按钮行为不变。
7. 切到「画面」→ 显示 显示模式 / 分辨率 两行。
7a. 切到「画面」后退出设置页，再重新打开 `PanelSetting` → 自动复位到默认 Tab「模型配置」。
8. 显示模式左右箭头 → 窗口化→无边框→全屏 切换；最左/最右箭头禁用。
9. 分辨率左右箭头 → 预置列表升序切换；最左/最右禁用；列表含 `1920x1080` 与常见 4:3。
10. 切换画面设置 → 重进 Title / 重启 → 保持上次选择（`game_settings.json` 生效）。
10a. **关键回归**：在「画面」Tab 激活状态下（`ContentModelConfig` 被隐藏）直接返回主菜单点「新游戏」/「继续游戏」→ 仍正确弹"未配置 API"提示（验证 `UIModelConfig` 挂隐藏节点后 `IsConfigReady()` 仍可调用）。
11. **可扩展性验证（可选）**：往 `mSettingsTabs` 临时加一项（如「游戏」+ 空内容区）→ 自动出现新 Tab 且可切换，验证后移除。

### 需求三（MsgboxSaveSetting，画面变更保存确认）
11a. 在「画面」Tab 改了显示模式/分辨率 → 在 `PanelTab` 按 ESC → 弹 `MsgboxSaveSetting`（三按钮）。
11b. 点「保存并退出」→ 写 `game_settings.json`，返回 `PanelMenu`；重进 Title 验证已保存。
11c. 点「退出」→ **还原为文件已保存值**（实际显示模式/分辨率与面板数值都还原），返回 `PanelMenu`；重进 Title 验证仍是旧值（未保存）。
11d. 点「取消」→ 关弹窗，留在设置页（`PanelSetting` 仍打开）。
11e. 画面设置**无任何变更** → 在 `PanelTab` 按 ESC → 直接返回 `PanelMenu`，不弹窗。

### 需求三补充（默认值，v0.23.4）
11f. 删除/首次运行（`game_settings.json` 不存在）→ 启动后应为 **全屏 + 1920x1080**；进入「画面」Tab 显示「全屏 / 1920 x 1080」。
11g. 保存过一次设置后 → 删除 `game_settings.json` 再启动 → 回到默认全屏 + 1920x1080（验证无文件时用默认值）。

### 通用
12. `MsgboxEmptyApiKey` 打开时按 ESC → 等价 Btn1（继续配置），不双重触发。
13. 反复 设置→子面板→返回→主菜单 → 状态稳定无抖动、无残留面板。
14. **PanelSetting 回归**：打开设置页 → 打开某配置子面板 → 返回 `PanelTab` → 切 Tab → 关闭设置页 → 再打开 → `PanelSetting` 全程保持激活；`UISetting`（Tab + 画面）与 `UIModelConfig`（`HasEmptyFieldInActivePanel`）判断始终正确；共用背景图不闪、不重叠。

## 6. 常见问题

| 现象 | 处理 |
|------|------|
| 文本框空了按 ESC 却不弹 EmptyApiKey | 检查 `UITitle.mEmptyApiKeyMsgbox` 是否拖入；`MsgboxEmptyApiKey` 是否挂 `UIMsgBox` |
| 点了 Tab 没反应 | 检查 `PanelSetting` 上 `UISetting` 的 `mSettingsTabs` 数组是否填入 `TabButton` + `Content`；Tab 按钮 **不要**手动绑 OnClick |
| 「画面」页箭头点了没变化 | 检查 `ContentDisplaySettings` 内控件是否拖到 `UISetting` 六个字段（画面逻辑并入 `UISetting`，非独立脚本） |
| 画面设置重启后没保存 | 检查 `Data/Config/game_settings.json` 是否生成；路径是否可写 |
| 退出设置页没弹保存确认 | 检查 `UITitle.mSaveSettingMsgBox` 是否拖入；`HasDisplaySettingsChanged` 是否判定有变更 |
| 「退出」后画面没还原（实际分辨率/数值仍是被改后的） | 检查 `UITitle.OnClickExitSetting` 是否绑到 `MsgboxSaveSetting` 的 **Btn2**（它调用 `UISetting.RevertDisplaySettings` 还原）；若绑错成 Btn1（保存）则会写盘 |
| 首次启动不是全屏 1920x1080 | 检查 `game_settings.json` 是否已存在旧值（有值则用文件值，非默认）；删除该文件后再启动即用默认值 |
| 文案显示成 key（如 `tab_model_config`） | 检查 `strings_zh_CN.json` 是否存在且 UTF-8；`UITextProvider` 是否已加载 |
