## 1. 背景与目标

### 1.1 现状

v0.22.16/v0.22.17 的 `SceneObjAnimator` 基于「动画 = FSM 状态」假设：组件订阅 `OnStateChanged`，收到 newState 后驱动 Animator。这覆盖了 Idle/Move/Dead/Hidden/Chase 等持续状态，以及转换边动画（起跑/刹车）和物理参数透传（跳跃阶段）。

但项目中存在大量**瞬时动作**，它们无独立 FSM 状态，却需要播放动画：

| 场景 | 是否有 FSM 状态 | 动画需求 | 现有架构能否处理 |
|------|---------------|---------|----------------|
| Idle/Move/Dead | 是（持续状态） | 循环动画 | 能 |
| 起跑/刹车 | 是（状态转换边） | 一次性过渡动画 | v0.22.17 能 |
| 跳跃阶段 | 是（Jump 状态内） | 物理参数驱动 | v0.22.17 能 |
| 按按钮/拉拉杆 | 否（瞬时动作） | 一次性动画 | 不能 |
| 背刺攻击 | 否（瞬时动作） | 一次性动画 | 不能 |
| 进柜子/爬梯子 | 动作触发状态切换 | 靠 FSM 驱动（不需额外机制） | v0.22.16 能 |
| 受击/格挡反应 | 否（瞬时反应） | 一次性动画 | 不能 |
| 拾取物品 | 否（瞬时动作） | 一次性动画 | 不能 |

### 1.2 问题本质

现有架构把「动画」和「FSM 状态」绑死。但游戏里有两类动画驱动源：

- **持续状态**（FSM 状态）：Idle/Move/Dead，有生命周期，由 `ChangeState` 驱动
- **瞬时动作**（行为/事件）：按按钮/攻击/受击/拾取，一次性，由业务事件驱动，不对应 FSM 状态

现有架构只有前者，后者无处安放。在旧架构上打补丁（加瞬时 FSM 状态 / 加旁路 PlayOneShot）本质上是在单 Layer 上手动模拟分层，逻辑分散且脆弱。

### 1.3 Interact 的额外复杂度：分发器 + 动画选择

经代码确认，`IInteractable.Interact()` 的 FSM 后果由被交互对象决定，调用方无法预判。据此交互分两类：

| 交互类型 | 例子 | 玩家 FSM 后果 | 动画怎么处理 |
|---------|------|-------------|------------|
| **状态切换型** | 柜子、梯子、门 | 变（Hidden/Climb） | 不播额外动作动画，靠 FSM 状态切换自然驱动底层动画 |
| **纯动作型** | 按按钮、背刺、盗窃 | 不变 | 用 PlayOneShot 播一次性动画 |

此外，同一个被交互物体在不同上下文下动画也不同：

| 交互对象 | 区域 | 动作 | 动画 |
|---------|------|------|------|
| 商人 | 正面 | Interact | 交易动画 |
| 商人 | 背面 | Interact | 盗窃动画 |
| 敌人 | 背面 | Interact | 背刺动画 |
| 敌人 | 正面 | Interact | 不播额外动画 |

**动画选择原则**：被交互物体在执行交互时，通过返回值携带动画标签枚举（如 `InteractAnimTag.Trade` / `InteractAnimTag.Steal` / `InteractAnimTag.Backstab` / `InteractAnimTag.None`）。被交互物体最清楚当前上下文（对象自身 + 区域 + 动作）对应什么动作，顺势返回标签。玩家侧的 `PlayerAnimator` 组件拿到标签后，用配置的映射表决定播哪个 Animator 状态。播不播动画完全由返回的 `animTag` 决定：非 `None` 就播，`None` 就不播，与 `success` 无关。这样既不违反开闭原则（新增物体不改玩家类），又不写死动画名（玩家决定标签对应什么动画）。

### 1.4 目标

重构动画系统，使其能统一处理持续状态动画和瞬时动作动画，且：

1. **FSM 保持干净**：不为瞬时动作加 FSM 状态
2. **支持瞬时动作**：按按钮/攻击/受击/拾取等一次性动画（纯动作型交互）
3. **状态切换型交互靠 FSM**：进柜子/爬梯子等不播额外动作动画，由 FSM 状态切换驱动
4. **交互返回值携带动画标签枚举**：被交互物体通过返回值返回 `InteractAnimTag`，`PlayerAnimator` 用映射表决定播什么动画，不违反开闭原则
5. **FSM 权威优先**：动作播到一半若 FSM 切状态，立即打断
6. **扩展性好**：未来新增瞬时动作类型不需改架构
7. **配置易用**：美术/关卡的 Animator 配置清晰直观

## 4. 功能需求

### 4.1 持续状态动画（保留现有能力）

FSM 状态切换驱动循环/持续动画。包括：
- 状态映射表（FSM 状态名 -> Animator 状态名）
- 转换边动画（v0.22.17）
- 物理参数透传（v0.22.17）

### 4.2 瞬时动作动画（新增）

业务代码触发一次性动画，播完自动结束。包括：
- Interact / Select / TextInput 动画
- 未来可扩展：受击/格挡/拾取等

### 4.3 动作与状态的关系

- **状态不变**（按按钮/背刺）：动作动画播完，回到动作前的状态动画
- **状态切换**（进柜子/爬梯子）：动作动画播完或被新状态打断，进入新状态动画

## 7. 已确认决策

| 项 | 决策 |
|----|------|
| 架构方案 | 方案 B（双层分离） |
| 动画选择机制 | 交互返回值携带 `InteractAnimTag` 枚举 |
| 枚举位置 | `SceneObj/Base/`（与 `IInteractable.cs` 同目录） |
| 动画组件拆分 | `SceneObjAnimator`（基类）+ `PlayerAnimator`（子类，Player 专属映射） |
| 接口返回值 | `(bool, string)` 改为 `(bool, string, InteractAnimTag)` |

| 播放规则 | 播不播完全由返回的 `animTag` 决定：非 `None` 就播，`None` 就不播，与 `success` 无关 |
| 上层清空策略 | 状态切换时全清 |
| 进柜子过渡动画 | 暂不考虑 |
| Select / TextInput 标签 | `InteractAnimTag.Select` / `InteractAnimTag.TextInput` |
| 上层 AvatarMask | 全身覆盖 |
